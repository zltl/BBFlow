# 安压宝小程序功能需求清单

## 一、整体说明

- 产品名称：安压宝（高血压人群血压管理工具）
- 形态：微信小程序
- 类目建议：工具 > 健康管理
- 定位：仅做健康数据记录与展示，不提供诊断和治疗结论

---

## 二、V1.0 核心功能需求（MVP）

### 1. 用户基础
- 使用微信登录（获取 openid 作为用户唯一标识）。（状态：部分实现，已完成微信登录与用户信息本地存储，尚未真正获取 openid ）
- 首次使用时展示简单引导页（1–3 屏），说明核心功能和免责声明。（状态：已实现）

### 2. 血压记录 - 手动录入
- 字段：
  - 收缩压（高压）：整数，单位 mmHg，范围 70–260。
  - 舒张压（低压）：整数，单位 mmHg，范围 40–150。
  - 心率：整数，单位 次/分，范围 30–200。
  - 测量时间：默认当前时间，可修改。
  - 标签：下拉多选或单选（如：清晨空腹 / 睡前 / 运动后 / 服药后 / 感觉不适 / 其他）。
  - 备注：可选文本，最长 50 字。
- 校验：
  - 超出范围时给出友好提示，可继续保存但标记为“异常”。
- 操作：
  - “保存”按钮，保存成功后提示“记录成功”，并返回上一页或清空表单。
 - 状态：已实现（表单字段、范围校验、保存与返回流程已落地，当前使用本地存储）。

### 3. 血压记录 - 拍照识别（OCR，V1 可占位或直接实现）
- 入口：在“记录血压”页面有“拍照识别”按钮。
- 流程：
  - 调用相机拍照，拍摄血压计屏幕。
  - 显示裁剪框，引导用户框住读数区域。
  - 将图片上传到后端服务器，调用 OCR 接口（具体实现可后置）。
  - 返回识别结果：高压 / 低压 / 心率。
  - 填充到表单中，用户可以手动微调后再保存。
- 异常处理：
  - 识别失败时给出提示“未能识别，请重试或手动输入”。
 - 状态：占位中（页面有提示文案，尚未接入相机与 OCR 能力）。

### 4. 本地或云端数据存储
- 方案一（起步简单）：先使用本地存储 `wx.setStorage` 保存血压记录列表。（状态：已实现，使用 key: `bp_records` 保存记录数组）
- 方案二（推荐）：使用后端服务器数据库存储。（状态：未实现，预留后续迁移服务器接口）
  - 字段示例：
    - `userId`：openid。
    - `systolic`：number。
    - `diastolic`：number。
    - `heartRate`：number。
    - `measuredAt`：datetime。
    - `tags`：array[string]。
    - `note`：string。
    - `createdAt`：datetime。
    - `source`：string（manual / ocr / bluetooth）。

### 5. 历史记录列表
- 展示最近一段时间的记录（例如最近 30 天）。
- 列表项内容：
  - 日期 + 时间。
  - 高压 / 低压 / 心率（用颜色标出异常范围）。
  - 标签（如有）。
- 支持按日期筛选（日期选择器）。
- 点击某条记录进入“记录详情”页，可查看全部信息（含备注）。
 - 状态：已实现（支持日期筛选与详情弹窗展示，数据来源为本地存储）。

### 6. 血压趋势图（基础版）
- 使用 ECharts（或小程序图表库）展示折线图：
  - X 轴：日期（最近 7 天 / 30 天）。
  - Y 轴：血压数值，高压和低压两条线。
- 支持切换：
  - 周视图：最近 7 天。
  - 月视图：最近 30 天。
- 可在图表上点选某个点展示具体数值。
 - 状态：未实现（尚未接入图表组件与数据聚合逻辑）。

### 7. 分享数据（V1 简易版）
- 功能：生成某一时间段（如最近 7 天）的数据概览图片。
- 内容要素：
  - 标题：安压宝 · 血压记录。
  - 用户昵称（可匿名处理）。
  - 时间范围。
  - 一个小趋势图（可用简单样式）。
  - 几个关键指标：平均血压、最高 / 最低值、异常次数。
- 操作：
  - 用户在“分享”页面选择时间范围 → 预览分享图片 → 保存到相册。
- 说明：
  - V1 可先实现“生成本地分享图片”，H5 链接分享放入后续版本。
  - 提供一版适合打印的报告图片样式（白底、清晰文字与网格），便于用户保存后打印或发送给医生。
 - 状态：未实现（暂未有分享页面与图片生成逻辑）。

## 三、V2.0 功能需求（智能增强）

### 1. 拍照 OCR 识别（完善版）
- 在 V1 占位基础上补齐细节：
  - 自动裁剪和倾斜矫正。
  - 识别结果增加置信度检查，明显不合理时提示“请重拍”。
  - 数值范围自动校验（例：高压 < 80 或 > 260 要醒目提示）。
  - 保留原始图片地址，便于之后问题排查（可选）。
 - 状态：未实现。

### 2. 用药记录与提醒
- 用药计划：
  - 字段：药名、剂量（如 10mg）、频次（每天 1 次 / 每天 2 次）、时间点（早 / 中 / 晚 / 自定义时刻）。
- 日常打卡：
  - 在首页或“用药”页展示今日用药列表，用户点击“已服用”。
- 提醒：
  - 使用小程序订阅消息，在设定时间前后发送“用药提醒”。
  - 用户可以选择是否开启提醒，并可随时关闭某个药品的提醒。
 - 状态：未实现。

### 3. 周报 / 月报自动生成
- 指标：
  - 平均血压（高压 / 低压）。
  - 最高 / 最低值。
  - 达标天数 / 超标次数。
  - 用药依从性（按打卡次数计算）。
- 展示：
  - 简单图表 + 概览文字，如“本周血压整体较平稳，请继续保持”。
- 分享：
  - 支持将周报 / 月报导出为图片（给家人 / 医生）。
 - 状态：未实现。

### 4. 分享 H5 报告（基础版）
- 用户在小程序中选择时间范围，点击“生成分享链接”。
- 小程序调用服务器接口生成：
  - 一次性 token。
  - 有效期（如 24–72 小时）。
- H5 页面功能：
  - 根据 token 拉取该时间段血压数据。
  - 展示趋势图与核心指标。
- 安全：
  - token 过期后不能访问。
   - 用户可在小程序中手动撤销链接。
 - 状态：未实现。

### 5. 报告文件导出（预留能力）
- 通过服务器接口根据用户和时间范围生成 PDF 格式的血压管理报告，并存储在服务器或对象存储中。
- 小程序内提供“下载 PDF 报告”入口，用户可在微信中打开并打印或转发给医生。
- 报告内容与 H5 报告保持一致（趋势图 + 关键指标 + 明细列表），布局适配 A4 打印。
 - 状态：未实现。

## 四、V3.0 功能需求（扩展 & 医生查看）

### 1. 蓝牙血压计同步（可选）
- 通过蓝牙连接指定型号的血压计，读取测量结果。
- 成功后自动生成一条血压记录，来源标记为 `bluetooth`。
- 在设置页维护“支持的设备列表”或连接说明。
 - 状态：未实现。

### 2. 医生端 H5 查看页
- 访问方式：
  - 医生通过患者分享的链接访问。
- 功能：
  - 查看指定患者某段时间的血压趋势图、关键统计指标。
  - 支持切换时间范围（如最近 7 天 / 30 天）。
- 不做的事情：
  - 当前阶段不做复杂医生账号、管理后台，仅做简单查看。
 - 状态：未实现。

## 五、跨版本的非功能需求

### 1. 数据安全与隐私
- 全程 HTTPS。
- 仅收集必要健康数据，不采集身份证号等敏感信息。
- 支持用户删除自己数据的入口。
- 提供隐私政策与用户协议入口。

### 2. 可用性与适老化
- 大字体、大按钮，高对比度配色。
- 操作路径尽量短：记录血压 ≤ 3 步。
- 关键提示使用简单中文，不使用复杂医学术语。

### 3. 系统与运维
- 错误日志记录（服务器日志 + 小程序端简单埋点）。
- 关键接口（如保存记录、生成报告）失败时有明确提示文案。
